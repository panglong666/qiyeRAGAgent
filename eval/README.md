# eval —— 知识库质量评测

评测脚本解决 README「已知局限」中这一条：

> 效果度量｜阈值 `RAG_MIN_SCORE` / `RAG_MIN_COVERAGE` 为经验值｜建立标注评测集，量化 Recall@K 与拒答准确率

## 运行

```powershell
.\.venv\Scripts\python.exe -m eval.rag_eval
```

- 不需要 `DEEPSEEK_API_KEY`：路由与拒答判定发生在调用大模型之前，评测结果与模型无关。
- 不写业务库：使用临时目录的独立 SQLite 与索引，不会污染 `data/`。
- 报告输出到 stdout，同时落盘到 `eval/last_report.md`。

## 作为回归门禁

```powershell
.\.venv\Scripts\python.exe -m eval.rag_eval --min-recall 0.6
```

Recall@4 低于门槛时以非零退出码结束，可挂到 CI。

## 指标口径（重要）

| 指标 | 含义 |
|---|---|
| 命中@1 / 命中@4 | 期望章节是否出现在 Top1 / Top4 引用中 |
| 误召回 | 域外问题被错误召回到制度片段 |
| 疑问句只读性 | 以问句形式提问时是否产生了写库副作用 |

**域内召回与域外拒答必须同时看。** 一个"什么都拒答"的系统，拒答准确率天然是 100%。
只看拒答率会得出与事实相反的结论，这也是本次评测把两张表并排的原因。

## 维护

- 题库 `IN_DOMAIN` 分 L1 原词直问 / L2 同义改写 / L3 口语化三层，用来区分"能背词"和"能懂意思"。
- 期望值是**章节名关键词**，改动手册后需要同步校对。
- 新增能力（如混合检索、重排）后重跑本脚本，用 Recall@4 的增量判断是否真的有效，避免凭感觉调参。
